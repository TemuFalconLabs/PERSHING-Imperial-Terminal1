# December 11 · DM quick start

**Before people arrive.** Open the Pages site with `?dm` on your laptop. Keep that browser profile for the evening. Choose MEN or KIDS, then **Create live session**. Send Matthew the displayed **Player link**, or have him enter the eight-character code on the home page. Both headers should say **CONNECTED · BOTH STATIONS**. The join code is separate from the prop code. Use one player browser per session. Keep the DM tab awake.

**At the table.** Matthew wakes the insignia and uses the directories. He or another player chooses PLAY. Register each real-world discovery using the current physical control on your dashboard. The first card shows the next action. Use Hint 1, 2 or 3 if they stall. Read notices aloud if the party is away from the laptop. Use Normal output during play. Fast mode accelerates transcripts as well as commands. Mute is available on either station. A player can pause a recording or replay it from the beginning.

**Keep a copy.** Export a checkpoint at breaks. The DM browser also retains the latest live state and automatic snapshots at relay 2 and final playback. After a brief loss, reconnect in the same browser with the same session link. If either computer stays offline, use **Continue on this laptop offline** on the DM screen and switch between Operator and Player view. For a cold start, download **offline.html** before game night, open it locally, select the same campaign, open the offline station and import your exported checkpoint. This is an independent continuation on one laptop. To resume live play, reconnect the original DM host and import the newer checkpoint there before handing the player terminal back.

**Emergency.** After the warning cuts off, let the alarm stand. Hold crisis while the players react. Release the hold and press **BEGIN CRISIS** once. Switch the tabletop map to its emergency version, keeping token positions. Describe impacts from the lab and both routes at the exit junction. The players may hold ground, retreat to reception, or head toward the caves.

## Short rehearsal

1. Use a disposable session, Fast mode and two different browser profiles or actual laptops. Confirm that DM changes appear on the other screen and commands appear in the watch log.
2. Follow the table once without visiting the equipment room or bench. Try the right code early and a wrong code after 004. Neither should unlock the lab. Pause 003, copy its four digits, then replay it.
3. Restore relay 2. Refresh Matthew’s page. Wake it and verify the lab is still available. Disconnect Wi-Fi briefly, then reconnect. Read both station headers before retrying a command.
4. Try a decoy. Deliver it to the ISB reader. Return to the vault for Sigma. Leave plant hatch open. Move party through lab to Director’s office, recover and insert her cylinder; obstruct her office door and test denial. Clear obstruction, confirm physical closure, then choose PLAY.
5. Hold the crisis through the final transmission. Release it expressly. Restore the before-final checkpoint if you want to rehearse the timing twice. Export a checkpoint and practice loading it into offline.html.
6. Create a fresh version 2 session for actual play; older checkpoint versions are incompatible. A reset is scoped to the selected session; never rehearse in the live group's active watch.

## Final development usability pass

Player terminal displays a six-spoke Imperial cog after 60 seconds of inactivity. Tap or press any key to wake; the overlay does not mutate session state, current objective, unlocked records or selected page. Playback, active processing and crisis screens are excluded. The archive and Director's terminal provide a return to the lab; entry to the Director's terminal still requires DM room selection. Ordinary unlocked stations provide a return to reception for earlier recording replays. HELP is visible from ordinary home directories. Follow the physical map and confirm actual discoveries; switching display does not replace table movement.
